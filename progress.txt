## Codebase Patterns
- Vitest config lives in `vite.config.ts` under `test` key; e2e tests excluded via `exclude: ['tests/e2e/**']`
- Unit tests go in `tests/unit/`, e2e tests in `tests/e2e/`
- Playwright uses chromium only, dev server auto-started via `webServer` config
- TypeScript strict mode enabled in `tsconfig.app.json`
- Scoring library lives in `src/scoring/` with barrel export via `index.ts`
- Test fixtures for poses go in `tests/unit/scoring/fixtures.ts` — use `makePose()` helper for partial keypoint data
- Pose estimation module lives in `src/pose/` with barrel export via `index.ts`
- TF.js MoveNet uses `@tensorflow-models/pose-detection` — must stub `@mediapipe/pose` via Vite resolve alias (see `src/stubs/mediapipe-pose.ts`)
- Sample dance pose JSON lives in `public/dances/sample-dance.json` — generated by `scripts/generate_sample_dance.py`
- App uses simple state-based routing (no router lib) — `view` state switches between 'home' and 'dance'
- React components go in `src/components/`
- Python pipeline lives in `scripts/` with own `requirements.txt`; tests via `python scripts/test_schema.py`

## 2026-03-14 - US-005
- Implemented key pose detection algorithm with three detection strategies
- Detects: held positions (low velocity), sharp transitions (high→low velocity), distinctive poses (deviation from neutral)
- Each key pose includes timestamp, expected pose data, type, and tolerance threshold
- Configurable via KeyPoseConfig: sensitivity thresholds, min gap, tolerance multiplier
- Files changed: src/scoring/keyPoseDetection.ts, src/scoring/index.ts, tests/unit/scoring/keyPoseDetection.test.ts
- 18 new unit tests (3 angular velocity, 4 distinctiveness, 11 key pose detection)
- **Learnings for future iterations:**
  - Key pose density controlled primarily by `minGapSeconds` — 3s gap gives ~10-20/min with varied choreography
  - Three detection types have different tolerance defaults: held (0.25), transition (0.3), distinctive (0.2) — transition is most generous because timing is hardest
  - `computeAngularVelocity` is average per-joint angular change — good proxy for "how much did the pose change"
  - Neutral angle map approximates standing pose — elbows/knees at PI (straight), shoulders at ~0.1*PI (arms at sides)
